# Integration Follow-ups

- Cognis browser provider loading imports scripts once and exposes no module-owned capability disposer or navbar mount/unmount contract. Jitsi therefore cannot fully unregister its browser `voip:startCall` capability and navbar listeners on disable, then restore them on enable, through the current public contract. Add a scoped browser provider lifecycle in Cognis before integrating the corresponding Jitsi disposer; do not delete another component’s capability registry or patch the page shell from this module.
- Cognis’s public `system:health:contribute` stores a callback without returning a disposer. Add a scoped health-contribution contract so enabled and disabled module registrations can release the callback on uninstall rather than retaining a closure over the module store.
- Keyring-dependent cleanup registration currently belongs to a private Auth capability without a public lifecycle-scoped disposer. Publish an owned cleanup contract or staged flow before adding Jitsi keyring-reset cleanup. Account deletion already uses the scoped `deprovision-user` hook; requesting the private registrar from a module does not establish a working integration.
