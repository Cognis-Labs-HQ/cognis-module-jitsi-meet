# ページコンポーネント互換性に向けたモジュール更新

ミーティング SPA ルートが Cognis コンポーネントページとして明示的に利用可能になりました。他のコンポーネントは、Jitsi Meet モジュールの UUID と安定したルート ID を使い、オーバーレイ、全画面、またはピクチャーインピクチャー表示向けに解決できます。

埋め込み側は、直列化可能なミーティング識別子を `focusState` で渡せます。ページは指定されたルート内にフレームレス Composer でマウントされるため、Host ナビゲーション、フッター、テーマ操作が重複しません。

コンポーネントページのルート識別子にはピリオド区切りの名前を使用し、呼び出し元がプラットフォーム標準のルート ID 規則で解決できるようにしました。

ミーティングのライフサイクルは、Jitsi の `conference.destroyed` エラーを終了済みミーティングとして扱い、退出後すぐに「ミーティングを開始」操作を復元するようになりました。埋め込み Jitsi ツールバーから参加者、パフォーマンス、背景の機能を除外しました。

オプションの Nextcloud Whiteboard ctx Capability が利用可能な場合、ホワイトボードボタンで一時キャンバスを作成し、同期されたコンポーネントウィンドウをミーティング画面内に開きます。接続を維持したままライブミーティングがピクチャーインピクチャーへ移動し、ホワイトボードを閉じると通常表示へ戻ります。

別モジュール経由でホワイトボードを作成するための Jitsi API ルート呼び出しを廃止しました。ホワイトボードボタンは、Whiteboard モジュールがオプションの Browser CTX Capability `whiteboard:uiGateway` を提供する場合だけ表示され、その `createDisposableCanvas` メソッドが Provider 作成を担当します。Jitsi はミーティング内のアクティブウィンドウ状態エンドポイントだけを保持します。

ホワイトボードの検出では UI をマウントせずに `component-pages:request` を使用します。一時キャンバスの準備後、ユーザーによるボタン操作でミーティングウィンドウの要素 ID を指定して `component-pages:spawn` を同期的に呼び出します。ブローカーが領域制限、ナビゲーション遮断、プロバイダーのクリーンアップ、返された破棄ハンドルを管理します。ミーティングのピクチャーインピクチャーは独自のコンポーネントウィンドウ配置を使わず、ブローカーの `component-page-stage` 状態に応答します。

ホワイトボードボタンを繰り返し押しても、開いているキャンバスを破棄しなくなりました。参加者ミーティングではリソースに紐づく安定したキャンバス ID をミーティングインスタンス間で保持し、参加者のいないミーティングは一時的なままです。ブローカーウィンドウと埋め込みページは画面全体を使用し、SPA の再マウント時には UI プロバイダーを明示的に読み込んで現在のミーティング用キャンバスを準備します。

ホワイトボードゲートウェイが見つからない場合、Meetings はホストのプロバイダーカタログを一度だけ強制更新し、起動時やモジュール更新後の古いカタログを無効化・有効化なしで修復します。コンポーネントウィンドウはブローカーの破棄ハンドルと画面単位のフォールバックを使用し、ルート全体の `component-pages:discardAll` クリーンアップは SPA シェルに委ねます。

SPA のマウント時にプロバイダーの準備状態を再試行し、新しく関連付ける各ミーティング画面へ衝突しにくい配置先 ID を割り当て、ホワイトボードをオーバーレイモードで要求するようになりました。これにより退避中または古い Meetings DOM への誤マウントと、領域内キャンバスの全画面ページ化を防ぎます。

起動したホワイトボードはフレームレス表示を要求し、画面に限定したワークスペース、パネル、セクション、グリッド、ウィジェットの余白上書きを使用して、ミーティングのピクチャーインピクチャーを維持しながらキャンバスを利用可能なミーティングウィンドウ領域へ広げます。

ミーティング PiP は Cognis コンポーネントページブローカーが全面的に管理するようになりました。このモジュールは PiP の配置コードやスタイルを保持せず、コアのフローティングウィンドウケイパビリティを直接呼び出します。コンポーネントのマウントと状態同期が完了するまでホワイトボードの有効化を保留し、ポーリングが進行中のマウントを破棄しないようにしました。

ホワイトボード表示で一時キャンバスとして扱うのは参加者がいないミーティングだけになり、ステージに参加者がいるミーティングでは通常のリソース連携キャンバスを開きます。

コアのフローティングウィンドウケイパビリティを、非同期のコンポーネントページ生成が始まる前に有効化するようにしました。ホワイトボードのマウント完了を待たず、ホワイトボードがステージを使用し始めた時点でミーティングが PiP になる、以前の正常な動作を復元します。

ホワイトボードのコンポーネントウィンドウ生成時に Cognis コアの `borderless` 契約フラグを設定するようにしました。ブローカーが外側のウィンドウ枠を取り除き、既存のフレームレスフォーカス状態が埋め込みホワイトボードシェルを制御します。

ホワイトボードボタンはコンポーネントウィンドウが有効な間、直ちに強調表示されます。強調表示されたボタンをもう一度選択すると、コンポーネントウィンドウを破棄し、ミーティングのピクチャーインピクチャーを解除して、既定のミーティング表示を同期します。

新しいミーティングの表示名を、生成された Jitsi ルームスラッグから派生させるようにしました。その一意な名前をミーティングのホワイトボードへそのまま渡し、関連する Messages チャットでは一意なミーティング名の後に作成日を付けます。

ボーダーレスのホワイトボードウィンドウで、固定高の領域に縦オーバーフローとして切り取るのではなく、コンテンツに合わせて Jitsi ステージが拡張するようにしました。ステージはコアのホストクラス `app-page__main--component-borderless` に応答し、重複していたモジュール側のコンポーネントウィンドウ余白上書きをコア契約に委ねて削除しました。

ホストレベルの `app-page__main--component-borderless` 上書きを削除しました。オーバーフローの原因は、後から読み込まれる Jitsi ステージ固有の `overflow: hidden` がコアの汎用 `component-page-stage` 動作を上書きしていたことでした。修正では `.jitsi-stage-frame-wrap.component-page-stage` を直接対象にし、ボーダーレスの子要素が自動ステージ高を決定できるようにします。

Meetings は、ホワイトボードキャンバスが存在する場合にだけ、ミーティング単位のオプション状態 `whiteboardOpen` を保存するようになりました。主催者は直ちに開き、主催者以外は参加状態に基づく票を過半数に達するまで蓄積します。開状態を検出したポーリングクライアントは共有キャンバスを自動生成してミーティング PiP を有効化し、後から参加するユーザーにも適用します。

ミーティングインスタンスの開始または引き継ぎ時に、すでに開いているミーティング単位のホワイトボードをリセットしないようにしました。これにより、参加者なしのミーティングで次の 5 秒間隔の状態更新時にホワイトボードが閉じる参加ライフサイクルの競合を解消します。明示的なミーティング終了時には引き続き共有ホワイトボードを閉じます。

5 秒間隔の状態エンドポイントが、初回のミーティング読み込みと同じ公開ミーティング状態形式を返すようになりました。保存された内部ホワイトボードフラグを `whiteboardOpen` にマッピングし、ポーリングが参加者なしミーティングの開いているホワイトボードを未設定と判断してコンポーネントウィンドウを閉じることを防ぎます。

Meetings は、アクティブなボーダーレス Whiteboard ハンドルを `component-page-stage--borderless` としてミーティングステージに反映するようになりました。そのハンドルが有効な間だけ、固定されたミーティングの高さとクリップされたステージのオーバーフローを緩和してコンポーネントキャンバスがステージを拡張できるようにし、コンポーネントの起動失敗時または終了時には既定の Jitsi レイアウトへ戻します。

Whiteboard コントロールをアンカーとして描画し、標準の `btn-confirm` アクティブ表示を使用するようにしました。主催者によるオープン状態の同期をコンポーネントページと PiP の有効化前に完了することで、初回のポーリングとマウントの競合による繰り返しのオープン失敗通知を解消しました。 一時的なコンポーネントマウントの起動失敗は、失敗トーストを表示する前に内部で再試行します。

アンカー形式の Whiteboard アクションに、モジュール側で完結するコントロールスタイルを追加しました。ホストのボタン既定値や管理画面専用の `btn-*` 宣言が利用できない場合でも、単なる下線付きリンクとして表示されず、アクティブ色の選択には引き続き `btn-confirm` を使用します。

Meetings は、ボタンパレット、コンポーネントステージのライフサイクル切り替え、スタイルシート挿入を重複実装せず、Cognis core の page-builder、再利用可能なページセクションスタイルシート、`ensurePageStylesheet` ユーティリティを使用するようになりました。これにより、非アクティブな Whiteboard アンカーがグローバルの青いリンク色を継承する問題も修正され、`btn-neutral` と `btn-confirm` は正規の core スタイルシートバンドルから提供されます。

Meetings は、新たに公開された `ui:reuse` 機能を、`ui/reuse/` 配下の本番モジュールと共通再利用スタイルシートへの唯一のブラウザゲートウェイとして使用するようになりました。小さなモジュール所有ファサードが機能の可用性を検証し、各 UI エントリポイントは使用するユーティリティだけを要求し、`page-sections.css` は機能経由で読み込まれ、重複していたスタイルシート挿入処理は削除されました。

ローカルの `ensureStylesheetLoaded` エクスポートを `ui:reuse` に委譲する形で復元し、現在の Meetings エントリポイントも同じエクスポートを使用するようにしました。これにより、混在した SPA キャッシュが古いルートエントリと新しいヘルパーモジュールを組み合わせ、名前付きエクスポート不足でモジュールのインスタンス化に失敗することを防ぎます。

Whiteboard のマウント失敗を現在の Meetings SPA マウント中は保持するようにしました。再試行不能な動的インポート失敗は直ちに停止し、準備またはマウントの最終的な失敗は一度だけ記録して「ホワイトボードの読み込みエラー」を表示し、ローカルの Whiteboard コントロールを無効化して、再読み込みまたは SPA 再マウントまで合意ポーリングによる再マウントを防ぎます。

Whiteboard アクションはアンカーのまま、すべての表示状態を Cognis core に委譲するようになりました。既定は `btn-neutral`、ホバー中およびアクティブ／オープン状態では `btn-confirm` を適用します。ホバーを外すと、Whiteboard が引き続きアクティブな場合を除いて `btn-neutral` に戻ります。

Whiteboard アンカーからモジュール固有の表示クラスを削除しました。既定、ホバー、アクティブ時の外観は Cognis core の `btn-neutral`、`btn-confirm`、`btn-animated` ユーティリティだけで提供し、モジュールはセマンティックな ARIA 状態と動作のみを保持します。

Meetings SPA は `page-sections.css` だけを読み込む代わりに、描画前に `ui:reuse` 機能の `loadCommonStyles()` 契約を呼び出すようになりました。これにより、標準ボタン表示を含む Cognis core の完全なスタイルシートカタログが、直接ナビゲーションと SPA ナビゲーションのどちらでも利用できます。

Whiteboard アクションは、隣接する共有アクションと同じネイティブ `<button>` および core の `btn-*` 契約を使用し、ネイティブの無効状態にも対応するようになりました。ボーダーレス生成ではコンポーネントコンテキストにもドキュメントスクロールのレイアウト契約を渡し、アクティブな Jitsi ステージはコンテンツサイズのグリッド行と可視オーバーフローを使用するため、埋め込みキャンバスが入れ子の縦スクロールを作らずに拡張できます。

ミーティング名は、保守されている暗号学的に安全なパスフレーズパッケージによって 4 語で生成されるようになりました。Whiteboard の準備では非同期結果を元のミーティングに固定し、提案されたキャンバスマッピングで保留中の合意を回避できないようにし、状態 API は真偽値以外の active 値を拒否します。

## アンインストール時のクリーンアップとローカライズ済みメタデータを追加

Jitsi Meet はアンインストール時に保存済み設定を削除し、要求された場合は保存済みの全ミーティングデータも削除できるようになりました。モジュールストアのメタデータは、モジュール所有の言語キーで翻訳されます。

## 使い捨て会議のチャットを削除

作成者と共有リンクだけの会議を閉じると、作成者の「メッセージ」にある関連チャットも削除されるようになりました。チャットの削除に失敗した場合は、安全にクリーンアップを再試行できるよう会議レコードを保持します。

## モジュール設定

## コアが表示する設定

Cognis がマニフェストで宣言された設定を表示し、モジュール所有の GET および PUT 設定エンドポイントと値を交換するようになりました。ブラウザーのログ、トースト、重大なエラー報告にはホスト機能を使用します。

## 品質基準

モジュールは Cognis の Prettier 設定と、構造、ローカライズ、命名、ドキュメント規約の独立した検証を使用するようになりました。

## ローカライズ済み文書テンプレート

コントリビューター向け文書テンプレートに、Cognis 標準からコピーしたドイツ語、英語、インドネシア語、日本語の各版を追加しました。

## 会議モジュールに共有 UI ゲートウェイを統合

会議の共有ボタンを中央の共有 UI ゲートウェイのコンテナインターフェース経由でマウントするようにしました。アイコン、ローカライズされたラベル、スタイル、ゲスト向け動作、破棄処理が Cognis の標準動作に統一され、現在の共有コンテキストでゲートウェイがトリガーを非表示にする場合でも、会議ページを引き続き使用できます。

共有リンクを使用するゲストだけが参加中の場合でも、会議の所有者がアクティブな会議に参加できるようになりました。

## ローカライズ済み README

ドイツ語、英語、インドネシア語、日本語の README と、英語版を参照する `README.md` シンボリックリンクを追加し、マニフェストの言語バンドル URL を検証する回帰テストを追加しました。

## ミーティング名と破棄可能なチャットの修正

ミーティングでは、Whiteboard と日付なしの Messages チャットに一意の4語名を一貫して使用するようになりました。参加者のいない破棄可能なミーティングではチャットを作成せず、既存の関連チャットも終了時に完全に削除します。Whiteboard ボタンのアクティブ表示も再描画後に維持されます。

## ミーティング共有ボタンの復旧

ミーティングウィンドウが使用する共有ポップアップ機能を宣言するようになり、参加者の入室後に Cognis が共有ボタンを表示し、標準の共有ダイアログを開けるようになりました。

## 参加者 Whiteboard の永続性を修正

ミーティングペイロードで招待済み参加者の有無を明示するようになりました。参加者がいるミーティングではプロバイダーの永続キャンバスファクトリを必須とし、破棄可能な作成へフォールバックしないため、関連付け済みキャンバスの自動保存が維持されます。

## Whiteboard の active クラスを修正

Whiteboard ボタンはコンポーネントウィンドウが開いている間、標準の `active` クラスを受け取るようになりました。選択中のナビゲーション項目と表示が揃い、ミーティングの再描画後もマーカーが維持されます。

## Whiteboard ボタンの検出を修正

Whiteboard ボタンは、プロバイダーの基本キャンバスファクトリとコンポーネントウィンドウ機能だけに依存するようになりました。永続キャンバスと参加者保存のオプションメソッドが、プロバイダーバージョンの読み込み中や更新中にコントロールを消すことはありません。

## Whiteboard の CSS 連携を縮小

Meetings は Whiteboard 固有の表示クラスを追加せず、共有コンポーネントウィンドウも上書きしなくなりました。コントロールはインポート済みのボタン状態を、コンポーネントはインポート済みのブローカークラスを使用するため、スタイルシートが移動後の SPA ページへ影響しません。

## Whiteboard のキーリングポップアップを修正

Meetings は Whiteboard コンポーネントウィンドウをマウントする前に、親ページからキーリングへのアクセスを要求するようになりました。ロック中のキーリングはロック解除ポップアップを表示でき、未処理の認証レスポンスでコンポーネントの読み込みが停止しません。

## Whiteboard の関連付け種別を修正

Meetings は、関連付けられた各 Whiteboard が破棄可能かどうかを保存するようになりました。参加者がいるミーティングでは、以前の連携が残した種別不明または破棄可能な関連付けを拒否し、自動保存が無効な破棄可能キャンバスを再度開かず、新しい永続キャンバスを要求します。

## Whiteboard のオープン表示を修正

Whiteboard が開いている間、ミーティングコントロールにアクセント背景付きのアクティブ表示を適用し、ラベルを「Whiteboard を閉じる」に変更します。選択すると現在のキャンバスが閉じることを視覚とテキストの両方で示します。

## Whiteboard の参加者同期を修正

Meetings では、破棄可能なキャンバスを参加者のいないセッションだけに使用するようになりました。永続的なミーティングキャンバスは全参加者に保存され、ミーティングとの関連付けから自動的に再度開きます。主催者と参加者のコントロールは同期された開閉状態に従います。

## Whiteboard のページシェルクリーンアップを修正

Whiteboard コンポーネントウィンドウのボーダーレス表示を Meetings ステージ内に限定しました。コンポーネントを閉じるか別ページへ移動するとローカル状態を同期的に削除し、共有 Cognis ページシェルをブローカー所有のボーダーレスモードへ変更しません。

## 永続 Whiteboard ゲートウェイを統合

参加者がいるミーティングでは、更新されたゲートウェイが公開する Whiteboard プロバイダーの `createCanvas` メソッドを、ミーティングタイトルと招待済み参加者ハンドルで正確に呼び出します。参加者のいないミーティングでは、引き続きリソースキー付きの `createDisposableCanvas` メソッドを使用します。
