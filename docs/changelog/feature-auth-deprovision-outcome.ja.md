# Jitsi のアカウント整理処理を認可する

**機能ブランチ:** feature-auth-deprovision-outcome

## Auth が確定した削除結果を必須にする

Jitsi 1.6.16 は、実行中のステージコンテキストと `system:contracts` を通じて `auth:deprovisionOutcome` プロトコル v1 を解決します。提供元が確認した確定済みの削除だけが、元のアカウントのクリーンアップを許可します。変更可能な入力や公開された永続化結果から、その権限を付与したり対象を変えたりすることはできません。契約が欠落または不適合の場合は安全側に停止します。従来の会議所有権、リソース削除順序、エラー処理、モジュールのライフサイクルを維持します。

## ホストとモジュールのリリースを調整する

この補完変更には、候補版 Auth 2.2.12 の結果契約と Core 0.6.6 の不変な flow ステージ参照が必要です。これは連携したリリースの依存関係であり、ホストが既に公開済みであるとの主張ではありません。モジュールを有効にする前に対応ホストを導入し、旧 Jitsi 利用側も更新してから、その整理処理が保護されたと判断してください。[PR #33](https://github.com/Cognis-Labs-HQ/cognis-module-jitsi-meet/pull/33) の検証済みゲスト受け入れの変更を維持します。旧ホスト向けの代替処理はありません。

## 登録済み flow で整理処理を検証する

合成テストは、エクスポートされた bootstrap と登録済みの整理・保存 flow を実行します。偽装結果、対象変更、呼び出しの対応付け、提供元の有効期間、リソース障害、任意の Whiteboard、無効化と再有効化、アンインストールを検証します。サーバーのみの変更であり、チュートリアルの操作項目や進行手順は追加しません。検証によって実際のアカウント、会議、外部リソースが変更されることはありません。
