# Jitsi Meet モジュール

Jitsi Meet モジュールは、参加者選択、再利用可能なミーティングルーム、セッション再取得、Messages チャット連携、オプションの共有 Whiteboard を備えた Cognis ネイティブのミーティング管理を提供します。

## 使用例

- ページ全体を遷移せずに `/meetings` と `/meeting` からミーティングへ参加または再接続する。
- 参加者を選択し、ミーティングアクセスを共有し、ミーティングの Messages チャットを使用する。
- Administration → Meetings で進行中および予定されたミーティングを監視する。
- Meetings ルートをオーバーレイ、全画面、またはピクチャーインピクチャーのコンポーネントページとして埋め込む。

## 技術仕様

- API 呼び出しには有効な Cognis アクセストークンが必要で、ミーティング詳細は承認済み参加者またはスコープ付き共有ゲストにのみ返されます。
- パスワードはミーティングレコードごとに生成されます。表示名は製品名の接頭辞がない一意の4語フレーズで、同じ名前が Whiteboard と日付なしの Messages チャットを識別します。参加者のいない破棄可能なミーティングでは Messages チャットを作成せず、以前に関連付けられたチャットも終了時に完全に削除します。
- モジュール所有の永続化領域に、設定、参加者、在席、ライフサイクル状態、Whiteboard 状態、合意投票を保存します。
- セッション再取得時には、ユーザーの以前のアクティブなミーティングセッションを切断します。

### 統合契約

- `bootstrap.js` が唯一のプラットフォームエントリポイントであり、ctx 機能とフローがコンポーネント間の唯一の統合面です。
- Meetings SPA は Cognis ルーターと Page Composer を使用します。埋め込み呼び出し元はシリアライズ可能な `meetingId` を `focusState` で渡し、埋め込みマウントはフレームレスでホストナビゲーションを重複させません。
- ブラウザユーティリティと共通スタイルシートの完全なカタログは、Meetings 画面を描画する前に必須の `ui:reuse` 機能から読み込みます。標準コントロール表示は Cognis core が提供し、モジュール CSS は Jitsi 固有レイアウトだけを所有します。
- オプションの Whiteboard 連携は、基本の `whiteboard:uiGateway` キャンバスファクトリ、コンポーネントページ、フローティングウィンドウ機能が利用できる場合に表示します。永続キャンバスと参加者保存のオプションメソッドは、ボタンの表示を制御せずに連携を強化します。破棄可能なキャンバスを使用するのは参加者のいないミーティングだけです。招待済み参加者がいるミーティングでは永続的なリソースキャンバスを使用し、その関連付けを全参加者に保存して、ミーティングの読み込み時に関連付け済みキャンバスを自動的に開きます。
- 主催者は Whiteboard を直ちに開けます。その他の参加者には、現在参加中の主催者以外の厳格な過半数が必要です。オープン状態は保存され、現在および後から参加するユーザーが同じキャンバスを自動的に開き、ミーティングをピクチャーインピクチャーへ移します。
- Whiteboard コンポーネントを開く前に、Meetings は親ページでキーリングへのアクセスを要求し、ロック解除要求にポップアップホストを提供します。その後、Whiteboard はコンポーネントページブローカーから、ドキュメント所有のスクロールを使う埋め込みオーバーレイコンポーネントとして起動します。Meetings はボーダーレス表示を Whiteboard ステージ内に限定し、コンポーネントを閉じるときにそのローカル状態を同期的に削除するため、SPA ナビゲーション後に共有ページシェルがボーダーレスのまま残りません。
- Whiteboard コントロールは、隣接する共有コントロールと同じ標準の `<button>` です。既定では core の `btn-neutral` 表示を使い、アクティブ時は選択中のナビゲーション項目と同じ `active` マーカーを `btn-confirm` とともに使います。アクティブなコントロールを選択すると、ミーティングの Whiteboard が閉じます。準備またはマウントに失敗した場合、Meetings はエラーを記録し、「ホワイトボードの読み込みエラー」を表示して、そのブラウザマウントではコントロールを無効にし、ポーリングによる再試行を防ぎます。再読み込み、または別ページへ移動して戻ると新しいマウントになり、再試行できます。
