# Jitsi Meet モジュール

Jitsi Meet モジュールは、参加者選択、ミーティング URL 再利用、セッション引き継ぎ、Messages アダプターのチャット再利用を含む Cognis ネイティブなミーティング制御を提供します。

## 使用例

- Cognis がマニフェストから表示し、モジュール所有の設定エンドポイントが保存する Jitsi インスタンス URL と任意の URI プレフィックス
- `/meetings` および `/meeting` アプリケーションルート:
    - ページから移動すると即座に停止する、ページ限定の稼働状況確認
    - ミーティング表示領域/オーバーレイ
    - 参加者選択とドラッグ＆ドロップ
    - Messages アダプターへのチャット URL 連携
- モジュール専用テーブルでのミーティング永続化
- ユーザー名ベースの参加者限定 API アクセス
- `classroom_id` 設定時の Classroom 参加者フォールバック認可
- 管理 → Meetings でのアクティブミーティング監視
- Social ゲートウェイ、Profile アダプター、Share ゲートウェイ、Messages アダプターへの UUID ベースの依存関係と、`auth:requireAuth` および `ui:profileAvatarRenderer` のケイパビリティベースのランタイム要件
- このモジュールの不変 UUID とルート ID `module.jitsi.meet.meetings` で解決され、オーバーレイ、全画面、ピクチャーインピクチャーに対応する、明示的に公開されたミーティングコンポーネントページ

## 技術仕様

- API 呼び出しには有効な Cognis アクセストークンが必要です。
- ミーティング詳細は許可された参加者にのみ返されます。
- ミーティングごとにパスワードを生成します。
- 各ミーティング名には生成された Jitsi ルームスラッグが含まれます。同じ一意な名前をホワイトボードへ渡し、Messages チャットのタイトルではその名前と作成日を組み合わせます。
- セッション引き継ぎで以前のアクティブセッションを切断できます。

### 統合契約

- `bootstrap.js` をプラットフォームが参照する唯一のモジュール入口とします。
- ブートストラップ ctx をこのモジュールの唯一の統合バスとし、API ルート、UI 登録、機能公開、将来の CLI/DB 配線を扱います。
- 他モジュールやコア内部への直接 import は禁止し、連携は ctx 経由に限定します。
- コンポーネントページの呼び出し元は、直列化可能な `meetingId` を `focusState` で渡します。埋め込み Mount は指定されたルート内だけに描画し、Host ナビゲーションを重複させないフレームレス Composer を使用します。
- ミーティング終了の検出は Jitsi の `conference.destroyed` エラーにも対応し、退出後すぐに「ミーティングを開始」操作を再有効化します。また、埋め込みツールバーから参加者、パフォーマンス、背景の機能を非表示にします。
- オプションの Nextcloud Whiteboard Browser Capability `whiteboard:uiGateway` が有効な場合、ミーティング画面に参加者がいるミーティングでは通常の永続的なキャンバス、参加者がいないミーティングでは一時キャンバスとなる同期ホワイトボードのコンポーネントウィンドウを表示し、ホワイトボードを閉じるまで接続中のミーティングをピクチャーインピクチャーで維持します。
- ホワイトボードの利用可否は UI をマウントせずに確認します。ユーザーのクリックでミーティング画面の要素 ID を指定して `component-pages:spawn` を呼び出し、ウィンドウを閉じるとき、またはミーティングページをアンマウントするときに返されたハンドルを破棄します。
- 開いたホワイトボードは、ミーティングが終了するか、強調表示されたホワイトボードボタンをもう一度選択するまでマウントされたままになります。招待参加者がいるミーティングではリソースに紐づくキャンバス ID を次回以降も保持し、参加者のいないミーティングは一時的なままです。SPA ナビゲーションで選択中のミーティングが変わると、プロバイダーの読み込みとキャンバス準備を安全に再実行します。
- キャッシュされたプロバイダーカタログにホワイトボードゲートウェイがない場合、統合を非表示にする前に Meetings が一度だけカタログを強制更新します。ウィンドウの破棄にはブローカーハンドルまたは画面単位の破棄フォールバックを使用し、グローバルな `component-pages:discardAll` は Cognis SPA シェルが管理します。
- SPA のマウント中にプロバイダーの準備状態を再試行し、レンダリングされた各ミーティング画面へ衝突しにくい配置先 ID を付与して、退避中または古い DOM が新しいコンポーネントウィンドウを取得しないようにします。ホワイトボードは全画面ではなくオーバーレイ表示を要求します。
- 起動したホワイトボードはコアのコンポーネントウィンドウ `borderless` 契約とフレームレス表示を要求します。そのコンポーネントハンドルが有効な間、Meetings は対応する `component-page-stage--borderless` 状態を適用して、ミーティングステージの固定充填高と切り取られたオーバーフローを緩和し、ボーダーレスのコンポーネントウィンドウがステージ高を決定できるようにします。
- Meetings はホワイトボードのコンポーネントページをマウントする前に Cognis コアのフローティングウィンドウケイパビリティを有効化するため、モジュール独自の配置やスタイルなしで、非同期のコンポーネント起動中もピクチャーインピクチャーが表示され続けます。
- ホワイトボードの開状態は、オプションのホワイトボードプロバイダーがキャンバス ID を提供した後にだけ保存します。主催者は直ちに開くことができ、それ以外の場合は現在参加中の主催者以外の参加者の過半数による要求が必要です。開いた後は、状態ポーリングによって現在および後から参加するユーザーにも同じキャンバスが自動的に開き、ミーティングがピクチャーインピクチャーへ移動します。Jitsi インスタンスの開始または引き継ぎではこのミーティング単位の状態を保持し、明示的なミーティング終了時に閉じます。初回読み込みと 5 秒間隔の状態更新は、同じ公開 `whiteboardOpen` 状態形式を使用します。
- Whiteboard アクションはアンカー形式のホストコントロールで、アクティブ時には `btn-neutral` から `btn-confirm` に切り替わります。主催者によるオープン状態の同期はコンポーネントページのマウント前に完了するため、状態ポーリングが進行中の初回マウントと競合せず、自動オープンでは同期済みの状態をそのまま再利用します。 一時的なコンポーネントマウントの起動失敗は、失敗トーストを表示する前に内部で再試行します。
- Meetings は、ホストの button 要素の既定値や管理画面専用のボタンクラスに依存せず、アンカーコントロール用のレイアウト、タイポグラフィ、ホバー、アクティブ、無効状態のスタイルをモジュール側で完全に提供します。
