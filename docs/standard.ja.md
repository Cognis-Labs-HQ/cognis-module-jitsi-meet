# Jitsi Meet モジュール

Jitsi Meet モジュールは、参加者選択、ミーティング URL 再利用、セッション引き継ぎ、Messages アダプターのチャット再利用を含む Cognis ネイティブなミーティング制御を提供します。

## 使用例

- Cognis がマニフェストから表示し、モジュール所有の設定エンドポイントが保存する Jitsi インスタンス URL と任意の URI プレフィックス
- `/meetings` および `/meeting` アプリケーションルート:
    - ページから移動すると即座に停止する、ページ限定の稼働状況確認
    - ミーティング表示領域/オーバーレイ
    - 参加者選択とドラッグ＆ドロップ
    - Messages アダプターへのチャット URL 連携
- モジュール専用テーブルでのミーティング永続化
- ユーザー名ベースの参加者限定 API アクセス
- `classroom_id` 設定時の Classroom 参加者フォールバック認可
- 管理 → Meetings でのアクティブミーティング監視
- Social ゲートウェイ、Profile アダプター、Share ゲートウェイ、Messages アダプターへの UUID ベースの依存関係と、`auth:requireAuth` および `ui:profileAvatarRenderer` のケイパビリティベースのランタイム要件
- このモジュールの不変 UUID とルート ID `module.jitsi.meet.meetings` で解決され、オーバーレイ、全画面、ピクチャーインピクチャーに対応する、明示的に公開されたミーティングコンポーネントページ

## 技術仕様

- API 呼び出しには有効な Cognis アクセストークンが必要です。
- ミーティング詳細は許可された参加者にのみ返されます。
- ミーティングごとにパスワードを生成します。
- セッション引き継ぎで以前のアクティブセッションを切断できます。

### 統合契約

- `bootstrap.js` をプラットフォームが参照する唯一のモジュール入口とします。
- ブートストラップ ctx をこのモジュールの唯一の統合バスとし、API ルート、UI 登録、機能公開、将来の CLI/DB 配線を扱います。
- 他モジュールやコア内部への直接 import は禁止し、連携は ctx 経由に限定します。
- コンポーネントページの呼び出し元は、直列化可能な `meetingId` を `focusState` で渡します。埋め込み Mount は指定されたルート内だけに描画し、Host ナビゲーションを重複させないフレームレス Composer を使用します。
- ミーティング終了の検出は Jitsi の `conference.destroyed` エラーにも対応し、退出後すぐに「ミーティングを開始」操作を再有効化します。また、埋め込みツールバーから参加者、パフォーマンス、背景の機能を非表示にします。
- オプションの Nextcloud Whiteboard ctx Capability が有効な場合、ミーティング画面に同期された一時ホワイトボードのコンポーネントウィンドウを表示し、ホワイトボードを閉じるまで接続中のミーティングをピクチャーインピクチャーで維持します。
